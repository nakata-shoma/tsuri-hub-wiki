# wiki-factcheck

TSURI HUB wiki([CLAUDE.md](../../CLAUDE.md)参照)の下書きMarkdownについて、「出典セクションに書かれたURL・書籍名などが、本文の記述を実際に裏付けているか」を検証するスキル。日本語校正・テンプレート準拠・出典の「有無」といった形式面は[wiki-proofread](../wiki-proofread/SKILL.md)の担当であり、本スキルは扱わない。

対象は既に本文に記載済みの出典のみ。新しい情報源を探す・裏取りするための追加のWeb検索は行わない(不足を発見した場合はユーザーへの提案に留める)。ファイル内容は自動で書き換えず、指摘事項をレポートとして提示する。修正の適用はユーザーの明示的な指示があった場合のみ行う。

## 対象ファイルの決定

引数: `$ARGUMENTS`

- `$ARGUMENTS` にファイルパスが指定されていれば、そのファイルを対象にする(複数可)。
- 指定がなければ、直近で作成・編集されたMarkdownファイル(会話内で扱ったファイル)を対象にする。それも不明な場合はユーザーに対象ファイルを確認する。
- 対象ファイルの「出典」セクションにURLが1件もない場合は、検証対象がない旨を報告し処理を終える(出典の欠落自体の指摘はwiki-proofreadの担当)。

## 検証手順

1. 対象ファイルの本文と「出典」セクションを読む。
2. 出典セクションに列挙されたURLごとにWebFetchで取得する。書籍名など取得不能な出典は、取得できない旨のみ記録し次に進む。
3. 取得結果をもとに、以下のチェック項目でレビューする。

## チェック項目

### 1. 到達可能性
- URLが取得できるか(404・ドメイン消滅・タイムアウトなどのリンク切れがないか)
- リダイレクト先が明らかに無関係なページ(ドメイン売却後の広告ページ等)になっていないか

### 2. 出典の性質
- 公的機関・メーカー公式・専門書籍・学術情報などの一次情報か、個人ブログ・まとめサイト・SNS投稿などの二次情報かを分類する
- 遊漁券・禁漁期間・禁漁区・サイズ制限などの法令・規則、および毒・応急処置など安全関連の記述(CLAUDE.md「情報収集時の注意事項」)は、二次情報のみに依拠している場合は必須修正として扱う

### 3. 本文記述との整合性
- 本文中の具体的な記述(数値・時期・生態・手順など)が、対応する出典に実際に書かれているか
- 出典の内容を誇張・拡大解釈・一般化しすぎていないか(例: 出典は「〜という説がある」なのに本文が断定になっている)
- 出典に書かれていない内容が、あたかもその出典の裏付けがあるかのように本文に書かれていないか

### 4. 出典間の整合性(出典が複数ある場合)
- 複数の出典間で内容が矛盾していないか
- 矛盾がある場合、本文がどちらの立場を取っているか、またその選択が妥当か

### 5. 単一出典への依存
- 重要な事実(特に上記2で二次情報と分類したもの)が1つの出典のみに依拠していないか
- 依拠している場合、追加の情報源での裏取りを推奨事項として提案する(本スキル自身では追加調査を行わない)

### 6. 確認日の妥当性
- 「確認日」から明らかに時間が経過しており、かつ変動しやすい情報(法令・規則、料金、営業時間など)である場合、再確認を推奨する

## 出力形式

以下の形式で日本語のレポートとして出力する。ファイルそのものは変更しない。

```
## ファクトチェック結果: <ファイル名>

### 検証した出典
- <出典名/URL>: 到達可否、一次/二次情報の別

### 必須修正
- [項目番号・チェック名] 該当箇所の引用 → 指摘内容(出典の実際の記述との差分を明示)

### 推奨修正
- (同上)

### 任意・提案
- (同上。追加の情報源での裏取り提案などはここに含める)

### 問題なし
- 該当項目を列挙
```

複数ファイルを対象にした場合はファイルごとにレポートを分ける。指摘件数が多い場合でも、必須修正から優先して提示する。

## 修正の適用

レポート提示後、ユーザーが修正の適用を明示的に依頼した場合のみ、Editツールで反映する。無断での一括修正は行わない。
